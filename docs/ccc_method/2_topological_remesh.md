# 拓樸改變:撕痕前進時網格怎麼即時改

來源:Weber 2006 §3.2(借用 Nienhuys & van der Stappen 的互動切割演算法,Delaunay-based)。
**問題**:撕痕前進 = 網格的拓樸改變(節點增刪、邊翻轉);要保持網格品質又不能太慢。

---

## 1. 撕痕末端前進時的網格調整(每步三條規則)

撕痕末端節點移到新位置後:

```
1. collapse:  若末端節點離某鄰居太近(< 門檻)→ 刪掉那個鄰居節點
2. split:     若末端後方的撕痕邊太長(> 門檻)→ 把該邊切分
3. Delaunay flip: 若某邊不符合 Delaunay 準則 → 翻轉它
                  (確保撕痕周圍三角形品質、避免退化三角形)
```

> **Delaunay 準則**:一條邊是 Delaunay 的,若兩相鄰三角形的外接圓不含對方的第三點。
> 不符合就 flip,使兩三角形的最小內角變大(品質變好)。每次末端前進都檢查周圍邊並視需要 flip。

> **「手術刀」由誰驅動**:原本 Nienhuys 的切割演算法由使用者移動手術刀;
> 這裡改由**撕裂演算法**(docs 06)驅動「刀」的移動。其餘 remeshing 流程照用。

## 2. 膜瓣怎麼「長大」— `Attached` 布林旗標(關鍵資料結構)

```
每個節點有布林旗標 Attached:
  Attached == TRUE  → 節點固定在水晶體表面初始位置,
                       排除在 mass-spring 模擬之外(還黏著,不動)
  Attached == FALSE → 節點加入 mass-spring 自由模擬(已剝離,會飄)

當「撕裂前緣(tearing front)」掃過某節點時:
  Attached: TRUE → FALSE          # 從黏著變剝離
```

- **撕裂前緣(tearing front)** = 一條連接「撕痕內外端」、投影到水晶體表面的線段,跟著末端前進。
- 撕囊 **< 360°**:前緣內端是網格中心的某節點。
- 撕囊 **> 360°**:前緣內端的節點也開始從水晶體剝離。

> 🔑 **精髓**:整張囊膜是一個 mass-spring 網格,但**只有 `Attached==False`(已剝離)的節點才參與物理模擬**。
> 撕到哪、就「解放」哪些節點進模擬。一個布林旗標就把「飄動的膜瓣」與「不動的囊膜」分開。
> (這個 `Attached` 旗標 = mass-spring 虛擬碼裡的 `fixed` 旗標。)

## 3. 撕裂判定可用 stretch 觸發(連回 mass-spring)

另一條更簡單的撕裂路線(EYESIM 用法):
```
當某條彈簧的 stretch = |當前長度 − restLength| 超過門檻 → 該彈簧「斷裂」
```
> 同一個 `stretch`:在 mass-spring 是「彈簧力大小」,在撕裂判定是「該不該斷」。
> Weber 2006 的 Indicator 法更進階(控制撕痕**方向**),stretch-break 法只控制**何時斷**。

---

## 真實度與取捨

- **on-the-fly remeshing + Delaunay** 能讓撕痕**平滑連續**,隱藏底層多邊形網格結構。
- 但網格解析度須配合切割演算法的門檻參數;太粗會露出多邊形痕跡。
- 因撕裂與囊膜模擬解耦,**整體仍滿足即時(≥30Hz)**。
