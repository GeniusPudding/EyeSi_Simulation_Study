名詞先解:volumetric locking(體積鎖死)

⚠ 為何 4 節點線性四面體「易鎖死」

軟組織近乎不可壓縮(ν → 0.5,幾乎是水)。4 節點線性四面體的形狀函數太「窮」——自由度不夠在每個積分點同時滿足「體積不變」又自由變形。結果元素為了硬湊不可壓縮約束,變得假性過硬、抗變形遠大於真材料,這就叫鎖死。

解法:高階元素、reduced-integration(單積分點)、六面體、混合 u–p 公式、F-bar…。Comas 2008 就是為此加了 reduced-integration 8 節點六面體——同自由度下元素更少、且不鎖死(代價:六面體有 hourglass 零能量模式,要加 Flanagan-Belytschko 控制)。

完整端到端路線圖

從離線建置到每幀即時迴圈的整條流程。

A. 離線建置(init,一次)

# 幾何 + 物理參數,上傳 GPU 建 mesh 水晶體=四面體 FEM(3000) 前囊=三角 FEM 橫向同性(1500) IOL=三角殼(743) 兩層網格 1 粗四面體 ─1→8─> 8 細(粗=力學/細=渲染+碰撞;8 細全刪→粗也刪) 纖維 逐三角給方向 θ:每 0.5mm 一圈同心圓(F=圓周切線) [初始化公式=推論] 預算 TLED:形狀函數導數相對原始構型=常數,預算一次上傳 GPU(texture 綁 linear memory) 材料 水晶體 1→5 kPa(依年齡) · IOL E=1MPa ν=0.42

B. 每幀即時迴圈(~30–80 fps)

1. 追蹤 6 台 IR 相機 → 器械位置/姿態(每器械 4 標記,VRPN,雙電腦) 2. 碰撞 器械(位置控制剛體)vs 組織 mesh → 接觸點;夾持:閉合把碰到節點約束到器械 3. 解算 隱式 + matrix-free CG(GPU):K 從不成形,逐元素算 K·v;異質組織用非同步預條件子加速 └ Comas 路線則是: 顯式中央差分逐節點更新(無解),兩 kernel gather 累加力 4. 撕裂 裂尖每方向 d 算 c=(σ_d⊥/σ̄_d⊥)·H((d·p)−cosθ_P);c>1 且 argmax → 撕一步 5. remesh 沿撕裂方向切分三角(每步);避免退化細三角(否則病態);matrix-free → 免重組矩陣 6. 移除 phaco:抽吸球內粒子加力拉向尖端;乳化=刪四面體 7. 渲染 Projected Tetrahedra 體積渲染(光沿深度衰減=手術視覺線索)+ 立體顯微鏡

🔑 步驟 3–5 的關鍵:matrix-free 讓「撕裂改拓樸」不必重組/重分解矩陣——這是撕裂能即時的根本。

引擎剖面:GPU TLED 逐步過程(讓真非線性 FEM 即時)

放大看 Comas 的引擎:顯式怎麼「不解方程」、每幀六步在算什麼、GPU 兩 kernel 怎麼拆。

顯式 vs 隱式:差在「下一步用不用到下一步自己」

傳統 FEM(隱式):解全域 K·U = F —— 這是靜力平衡(內彈力=外力)離散到網格。K 是剛度矩陣,把所有節點耦合(動一個節點會拉扯鄰居)→ 要解一個所有節點同時自洽的大方程,貴、順序相依、難平行。

TLED(顯式):下一步位置只用「現在已知」的量算,不引用未知的下一步狀態 → 沒有方程可解、每節點獨立:

uₙ₊₁ = 2uₙ − uₙ₋₁ + Δt²·M⁻¹·(F_ext − F_int(uₙ)) M=對角(集中)質量 → M⁻¹ 只是逐節點除以質量

代價:顯式只看當下受力,Δt 太大會衝過頭→爆掉(條件穩定);隱式看「未來構型」的受力→無條件穩定但要解方程。軟組織剛度低→顯式 Δt 上限較寬→划算。所以「每節點獨立算自己的下一步位置」是顯式的結果,不是定義本身——定義是「不引用未知的下一步」。

每幀六步(給定節點位置 → 算彈力 → 走一步)

每元素(GPU thread=一個元素): a. 讀節點位置 → 變形梯度 F(原始小箭頭 dX 變成 dx:dx=F·dX,含拉伸+旋轉) b. C = FᵀF(扣掉旋轉、只剩純拉伸)→ 套材料本構律 → 應力 S c. strain-displacement 矩陣 B(由形狀函數空間導數組成:應變 ε = B·u) d. 由 S 算「這元素對它每個角節點的力貢獻」 每節點(GPU thread=一個節點): e. gather 鄰元素的力貢獻加總 → 節點淨內力 F_int f. 中央差分更新位置(上面那條式)

整體 = FEM 版的「算彈簧力 → 積分 F=ma」,只是力來自真連續體力學(F→C→S)而非虎克彈簧。為何應變要形狀函數空間導數:應變=位移在空間中的變化率;元素內位移 u(x)=ΣNᵢ(x)·uᵢ,故 ε ∝ Σ(dNᵢ/dx)·uᵢ——那個導數就是 B。Total Lagrangian 讓這些導數相對原始構型=常數,預算一次、每步查表。

GPU 兩 kernel:是「兩趟平行」,不是把 GPU 切成兩半

kernel = 一段程式,一發射就在幾千個 thread 上同時跑同一段碼、每 thread 處理一筆資料。兩個 kernel = 兩趟(先後)的全域平行掃描,每趟都用整顆 GPU:

Kernel 1(thread=元素):算 a–d,把力貢獻寫進「自己獨佔的格子」 ── 整顆 GPU 掃一遍所有元素 ▼ Kernel 2(thread=節點):gather 加總 → e–f 更新位置 ── 整顆 GPU 掃一遍所有節點

拆兩趟是為了避開寫衝突:若一趟就讓元素直接寫共用節點,多個 thread 同寫同一位址=race condition。翻成「寫私有格子(Kernel1)+ 讀共用來 gather(Kernel2)」→ 衝突消失(scatter→gather)。「拆兩半」是時間上的兩趟,不是空間上切 GPU。

⚠ 這顆引擎只做變形——撕裂/接觸/觸覺怎麼辦?

Comas TLED(顯式)不做撕裂、接觸、觸覺(顯式對接觸力不穩)。解法不是硬擴充它,而是換另一套引擎接手:

撕裂Allard 2009:co-rotational + 隱式 + matrix-free CG + argmax c 準則 + remesh
接觸/穩定Courtecuisse 2010:GPU-CG + 非同步預條件子(隱式才穩得住接觸)
完整系統Dequidt 2013:上兩者 + phaco(刪四面體)+ IOL(殼+摩擦接觸)+ IR 光學追蹤

→ 這就是「兩套引擎」:純變形用 TLED 顯式;要撕裂/接觸就切 co-rotational 隱式 matrix-free。在 SOFA 裡 = 每個部件掛合適的 ForceField + Solver。

撕裂 + remesh:具體怎麼做

斷裂準則(Marchal Eq.4–6,Dequidt 沿用)

c(d,σ,f,p) = σ_d⊥ / σ̄_d⊥ · H((d·p) − cosθ_P) , d⊥ = d×n (Eq.4) σ_u = cos²θ_u·σx + sin²θ_u·σy + 2 sinθ_u cosθ_u·τxy (Eq.5 Mohr 投影) σ̄_u = σ̄_T + (σ̄_F − σ̄_T)·[1 − (2/π)·acos(|u·f|)]^α (Eq.6 方向強度內插) 撕裂方向 = argmax_d c (c>1 才撕)

σ_d⊥=垂直撕痕的張應力(撐開裂縫的 Mode-I 分量,非沿 d 的力)。σ̄:u∥纖維→強 σ̄_F、u⊥纖維→弱 σ̄_T。H(·):只准與上一步 p 夾角≤θ_P(防回折)。等向退化 = 最大主應力準則(Marchal 明證)。

何處/何時:裂尖或潛在裂元素中心;粗網格單元素應力不準→鄰域加權平均平滑;不做 substepping(大 dt 取 argmax)。Dequidt 正文用 stress 特徵值(非 strain),門檻依外科醫師調。

remesh 兩策略:沿既有邊(便宜、mesh-dependent)或任意方向切分(mesh-independent,須避免退化細三角,引 Federl)。每步做。

器械力怎麼來?(修正「速度推算」的誤解)

⚠ 不是力回饋裝置、也不是用光學追蹤速度推算

光學追蹤給的是位置/姿態(每幀),不是力。力是接觸/約束模型的輸出,由器械位置「推/夾」組織而生。速度只影響動力學/阻尼,不是力來源。

IR 光學追蹤 ── 每幀器械位置/姿態(非力、非速度) │ ▼ 器械 = 位置控制的剛體障礙 / 夾持物 │ ├─ 推:碰撞偵測 → 接觸模型(penalty / constraint;Saupin contact-warping + 摩擦) → 組織受接觸力 └─ 夾:鑷子閉合 → 把碰到的節點約束到器械 → 移動器械 = 拉那些節點 → mesh 生張力 │ ▼ 隱式 FEM 回應 → 組織變形 → 張力超門檻 → 觸發撕裂(argmax c) │ ▼ 反力理論上可導出(可接觸覺),但此系統無力回饋裝置 │ ▼ 醫師手感 = 只有視覺回饋 + 眼球模型的機械約束(插針孔/眼窩限制器械運動)

✔ 一句話

器械是位置驅動的(追蹤給位置)→ 碰撞/夾持約束產生組織受力 → 隱式 FEM 算變形與撕裂。沒有力回饋到醫師手上,回饋是視覺 + 眼球機械約束。所以「用速度推算力」不成立。

效能真相(修正「INRIA 慢」)

全在 2.4 GHz + 一般顯卡。「5 fps」只是 IOL 那步,不是整個系統。
