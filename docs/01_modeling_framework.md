# 01 — 建模框架:物理式 vs 描述式、彈性理論

來源:Schill 2001, Ch2–Ch3。這是理解所有後續演算法「為什麼這樣設計」的鑰匙。

## 建模循環(任何模型都跑這 6 步)

1. 觀察問題、找規律 → 2. **理想化(idealization)** → 3. 建數學模型 + 起始/邊界條件
→ 4. 解、做預測 → 5. 實驗驗證 → 6. 修正 → 回到 1。

> ⚠️ **最致命的錯在第 2 步「理想化」**:理想化錯了(例如把高度非線性的囊膜假設成線性),
> 後面演算法再精確、解再準,都只是「那個錯誤假設」的正確答案。理想化錯 = 地址抄錯,開再快也到不了。

## 物理式(physical) vs 描述式(descriptive)

| | **Physical 物理式** | **Descriptive 描述式** |
|---|---|---|
| 本質 | 用物理定律建構(微分方程) | 把觀察到的行為參數化 |
| 參數 | 有物理意義、**可量測**(E, ν) | 自由參數,靠**擬合/手調** |
| 模的是 | 過程的**功能(how it works)** | 過程的**行為(what it looks like)** |
| 驗證 | 容易(參數可量測) | 難(可能只在擬合條件下對) |
| 速度 | 慢、貴 | **可以非常快** |
| 代表 | FEM | ChainMail、純幾何 |

### 建模金字塔
所有方法排成一條**連續光譜**(邊界是軟的):
```
FEM ──── mass-spring ──── 粒子 ──── ChainMail ──── 純幾何
◄──物理 physical                      descriptive 描述──►
慢·準·可量測                              快·近似·靠調參
```
**選方法的方向 = 由約束反推**:要即時 VR 模擬器 → 必須往描述端 → FEM 自動出局。
這就是 EyeSi 選 ChainMail / mass-spring 的邏輯起點。

> Schill 的大趨勢觀察:物理方法為了即時都被「簡化成描述式」(假設靜態、線性、手調彈簧係數);
> 而 **ECM 反向操作 = 描述式打底 + 物理鬆弛修正**。

## 彈性理論(黃金標準,知道它才知道在近似什麼)

連續體力學,兩個可量測物理參數:

- **楊氏模量 E(Young's modulus)= 材料多硬**
  - 定義:應力 ÷ 應變(stress / strain)= 施加多大壓強,相對伸縮多少。
  - E 大 = 硬(鋼、骨);E 小 = 軟(玻璃體、囊膜)。眼科組織 E 很小 → 又軟又難模。
- **蒲松比 ν(Poisson ratio)= 壓一方向、旁邊鼓多少**
  - 定義:橫向收縮應變 ÷ 縱向伸長應變(無單位)。
  - ν ≈ 0.5:體積幾乎不變(生物軟組織多接近 0.5,富含水、近不可壓縮)。

> **為何不能直接用彈性理論**:精確套用會得到無法解析、數值不穩、或超出即時時限的算式。
> 所以要近似 → mass-spring / ChainMail。
> **E 管軟硬,ν 管被擠壓時形狀/體積怎麼重新分配。**
