# 商用級 CCC 撕裂:架構決策 A(硬化 remesh)vs B(預裂 + 內聚鍵)

目標:**商用穩定**的連續囊膜撕裂 —— 模擬器絕不能在術中崩、要即時 + 觸覺、撕痕要隨器械拉法真實反應、還要重現「裂縫往周邊逃逸(Argentinian flag)」這個受訓要防的失敗模式。

本文只做一件事:把兩條路在**這個具體場景**下攤開比較,給出建議。脈絡見 [`../ccc_method/4_inria_fiber_fracture.md`](../ccc_method/4_inria_fiber_fracture.md)、[`../reference/7_han2021_fem_tearing.md`](../reference/7_han2021_fem_tearing.md)。

---

## 0. 場景與需求(先把規格釘死)

囊膜物理:直徑 ~10mm、厚 ~5–30μm 的膠原膜,高度彈性、**同心圓纖維各向異性**(圓周強、徑向弱)。撕囊 = 造一個小起始瓣 → 鑷子夾住 → 撕出連續的圓形開口(~5–5.5mm)。

商用訓練器的硬需求(依重要性):
1. **絕不崩**(術中卡死/NaN = 產品死刑)。
2. **即時**:力學迴圈 >30 FPS;若接觸覺裝置,觸覺迴圈需 ~500–1000 Hz。
3. **撕痕真實可控**:方向、速度隨鑷子拉法變化。
4. **重現徑向逃逸**:纖維導致撕痕想往周邊跑 —— 這正是受訓要練的控制。

這四條裡,**第 1 條(絕不崩)是商用與研究的分水嶺**,也是評分的最高權重。

---

## 1. 架構 A:硬化 remesh(Allard 2009 路線)

**做法**:三角 FEM 膜;應力超門檻時,沿裂縫方向**切分三角形、局部 remesh、繼續模擬**。裂縫尖端在哪、往哪走,網格就跟著改。

**優點**
- **保真度最高**:裂縫沿真實應力場走任意方向、任意曲率,網格與裂縫完全貼合。Allard 的結果看起來真,就是這個原因。
- 最忠於 2008/2009 論文。

**致命難點:即時拓樸 remesh 的穩健性**
局部切割每一步都必須同時避免:
- **退化(sliver)三角形** → FEM 剛度病態 → NaN / 負質量 → 崩(← 我們實測到的正是這個)。
- T-junction、非流形邊、裂縫路徑不連續(← log 裡的 `Edges are not connected`)。
- 切割後質量矩陣、約束索引失效(← `ConstantForceField 索引超出系統大小`)。

要對**所有**構型都 bulletproof,是公認的難題。**連 INRIA 的研究碼都是研究等級**,論文特別花篇幅講「必須避免退化三角形」—— 這句話本身就說明它有多容易壞。

**效能**:remesh 改變矩陣大小與稀疏結構 → 無法預分解;matrix-free CG 可緩解,但拓樸變更本身有成本。囊膜規模(~1–2k 三角形)可即時(Allard 證明過),但穩健防護會再吃效能。

**工程/建置成本**:必須改 SOFA 的拓樸演算法(`TriangleSetGeometryAlgorithms` / Tearing 的 `splitting`)→ **要改 C++ 核心 + 從源碼重編**。最重。

**商用風險:高。** 失敗模式就是術中崩,對產品不可接受;需要極大量的構型 robustness 測試才敢出貨。

**GPU:不能用。** 執行期改拓樸與 GPU(CudaVec3f)不相容 → **A 用不到 Comas 2008 的 GPU 引擎**。

## 2. 架構 B:預裂 + 內聚鍵(cohesive zone)

**做法**:囊膜**預先**細三角化;把共用節點**複製分身**,元素之間用**可斷的內聚鍵(cohesive/interface 元素或斷裂彈簧)**連著。當鍵上的張力(traction)超過材料的分離律(traction–separation law)→ **鍵斷開**。「撕」= 斷鍵。**執行期完全不改網格拓樸。**

**優點**
- **穩定性:磐石級。** 網格拓樸永不改變 → 剛度矩陣結構固定(斷鍵只是把某個貢獻歸零)→ **永遠不會產生退化元素 → 結構上不可能因 remesh 崩**。這就是商用/遊戲撕裂偏好它的原因。
- **物理其實更紮實**:內聚區模型(CZM)是計算斷裂力學的**標準**方法(**你 `reference/7` 的 Han 2021 用的正是 cohesive law**)。B 不是「比較不物理」,它的限制是**幾何**(裂縫走預設邊界),不是物理。
- **各向異性可直接編碼**:把**徑向的鍵設弱、圓周的鍵設強** → 撕痕自然往徑向逃逸 → **直接重現 CCC 的關鍵失敗模式**,而且比 A 更好調。
- **效能好、可上 GPU**:固定拓樸 → 矩陣可預分解 / 稀疏結構穩定 → 快、且**適合顯式 TLED on GPU**。→ **B 正是能真正用上 Comas 2008 GPU 引擎的路**:固定拓樸 + 顯式 = SofaCUDA 的天菜。斷鍵 = 歸零一個貢獻,極便宜。

**缺點**
- **裂縫路徑受限於預設元素邊界** → 會有輕微階梯狀(stair-stepping)。緩解:用**夠細、品質好的網格**(Delaunay 等向三角化,不是同心圓環)。夠細時肉眼幾乎看不出。
- 需要一次性的**網格前處理**(節點分身 + 建內聚鍵),以及調分離律參數讓手感對。

**工程/建置成本:中,可能偏輕。** SOFA 有可斷彈簧類元件;內聚律的判斷邏輯可用 **Python controller** 做。**很可能不需要從源碼重編 SOFA** —— 大半用 stock 元件 + 一個 controller 就能起步,要更真再寫一個輕量 C++ 內聚元素。

**商用風險:低(穩定性面)。** 主要工作在調網格細度與分離律,讓撕的樣子與手感對、並重現徑向逃逸。

## 3. 正面對決(針對囊膜撕裂)

| 面向(權重) | A 硬化 remesh | B 預裂內聚鍵 |
|---|---|---|
| **絕不崩(★★★★★)** | 🔴 穩定性地雷區,難 bulletproof | 🟢 結構上不可能因 remesh 崩 |
| 即時 + 觸覺就緒(★★★★） | 🟡 可即時,防護吃效能;拓樸變更難配 1kHz 觸覺 | 🟢 固定矩陣、可預分解,最適合高頻觸覺 |
| 撕痕保真(★★★） | 🟢 任意方向/曲率,最真 | 🟡 沿預設邊界,細網格可逼近 |
| 徑向逃逸失敗模式(★★★） | 🟢 由纖維各向異性自然湧現 | 🟢 由各向異性鍵強度直接編碼 |
| 物理理論基礎 | Allard argmax-c(等向退化=Rankine) | **CZM / Han 2021 cohesive law**(斷裂力學標準) |
| 用得上 Comas GPU？ | 🔴 不能(拓樸變更 vs GPU) | 🟢 能(固定拓樸+顯式 TLED) |
| 需要改 C++ 核心 + 重編 SOFA | 🔴 幾乎必須 | 🟡 可先免,後續選配 |

**一個漂亮的綜合點**:A 用不到 GPU,B 反而**同時能用「Comas 2008 GPU 引擎」+「穩定撕裂」** —— 走 B 才真正把 2008(GPU 即時)和撕裂兩塊合起來。

**對映到你的論文**:A = Allard 2009(remesh + argmax-c);B = Han 2021(cohesive law)。你 `reference/7` 已標註這是**兩套不同的斷裂框架**。所以 A/B 的選擇,本質是「選哪一篇當實作母體」。

---

## 4. 建議

**商用穩定 → 選 B(預裂 + 各向異性內聚鍵)。** 理由:產品第一需求是「絕不崩」,而 B **在結構上保證**這點;A 是把整個領域最硬的穩定性問題正面扛下來,連研究等級都不見得 bulletproof。B 在保真度上的犧牲(路徑階梯)可用細網格補到肉眼無感,而且它的物理母體(CZM)是斷裂力學標準、又能重現徑向逃逸、還能上 GPU。

**進階(有餘力再做)**:B 為穩定核心,**裂縫尖端附近做局部 remesh 精修**(hybrid),兼顧穩定與保真 —— 但這是第二階段,不是起點。

## 5. B 的實作草圖(若選 B)

```
前處理(一次性):
  1. 用等向 Delaunay 把囊膜圓盤細三角化(品質好、無 sliver)。
  2. 沿所有內部邊「拆縫」:每條共用邊的兩側節點複製分身。
  3. 每對分身之間建「內聚鍵」:法向/切向的可斷連接,
     鍵強度依同心圓纖維 → 徑向鍵弱、圓周鍵強(各向異性)。

執行期(不改拓樸):
  - FEM 照常算元素內力(可 CudaVec3f 上 GPU)。
  - controller 每步檢查每個鍵的分離量/traction;
    超過分離律門檻 → 斷該鍵(把其剛度貢獻歸零)。
  - 斷鍵集合 = 當前裂縫。鑷子(器械)拉動 → 局部 traction 上升 → 沿最弱方向(徑向)斷 → 撕痕往周邊逃逸。

穩定性來源:矩陣結構永不變、無退化元素、可預分解 → 絕不崩、且快。
```

需要的元件:多半 stock(FEM、彈簧/約束、mapping、碰撞)+ **一個內聚律 controller(Python 起步)**。要更真再寫輕量 C++ 內聚元素。**起步很可能不需要從源碼重編 SOFA。**
